# FlowPlace 论文框架

FlowPlace 是一个用 Flow Matching 训练的条件生成模型：输入电路的宏块尺寸、引脚连接和当前坐标，逐步生成宏布局，再交给后端工具完成标准单元放置和布局布线。它的模型在合成数据上离线训练，测试时零样本生成，不需要针对每个真实电路进行在线 RL 或微调。方法按训练数据、模型与训练、采样约束三部分整理。

## 第一部分 训练数据怎么构造

每个样本是“电路题目 G＋对应宏布局 x1”。采用逆向构造：先生成没有宏重叠的布局，再按空间邻近关系生成引脚偏移和连接，得到与该布局配对的网表。这样能扩大训练数据量，但合成布局不等于经完整 PPA 优化后的专家布局。

相对纯随机摆放，FlowPlace 加入了“大宏块倾向靠边，给中心区域留空间”的 domain prior。具体做法是按宏面积从大到小生成布局，把画布划成 128×128 网格；先用二值 mask 排除越界、重叠位置，再让距边界近的位置有更高采样概率，偏好分数为“1 / (到边界距离＋ε)²”。位置采样概率同时受合法性 mask 和这个分数控制。

公开 mask 数据生成配置中，宏块数量上限为 400，停止放置的目标密度从 0.65～0.80 采样。发布模型附带的训练配置记录了 40,000 个训练样本和 2,000 个验证样本；这属于发布包元数据，本次没有重新生成该数据集，也没有独立重建其完整生成过程。

需要区分两个 prior：上述 domain prior 是构造训练布局时的结构偏好；后文 uniform prior 是生成开始时坐标噪声的分布。两者作用不同。

## 第二部分 模型结构 训练与推理

这里是 **GATv2，不是 GAN**。GATv2 属于图神经网络；它和多头自注意力共同组成速度预测网络。

输入包括当前宏坐标 xt（N×2）、当前进度 t，以及电路图 G。节点条件特征为归一化宽高（2 维），边特征为连接两端的引脚偏移（4 维）；固定端口通过 mask 标识。实现使用 edge_index 保存连接，不要求构造稠密的 N×N 邻接矩阵。以下 N 表示图中节点数，包含实现加入的固定端口节点。

| 部分 | 做什么 | 官方发布配置与实现 |
| --- | --- | --- |
| 输入编码 | 把当前坐标、宏尺寸及固定节点信息转成隐藏特征 | 隐藏维度 256；input_encoding_dim=32 |
| GATv2 | 沿网表连接聚合邻居信息，理解局部连接需求 | 4 个头，拼接后 256 维，即每头 64 维 |
| 多头自注意力 | 让各宏利用全局信息，考虑远处宏之间的关系 | 4 个头，隐藏维度 256，输出仍为 N×256 |
| 中间 MLP | 对每个节点的特征进行非线性变换 | 两层，256→1024→256，带残差和 LayerNorm |
| 时间条件 | 告诉网络目前处于生成过程的哪个阶段 | 32 维正弦时间编码，通过 FiLM 调节 GNN 特征 |
| 最终输出 | 为各节点预测 x、y 两个方向的速度 | 代码最后为 256→2 线性解码并加输入坐标残差；输出 N×2 |

整体重复三个阶段，每阶段为“两层 GATv2 的残差块 → MLP → 一层 GATv2 与全局自注意力组成的块 → MLP”。按实际代码合计 9 层 GATv2、3 个全局自注意力块、6 个中间 MLP；dropout=0。论文将输出端概括为 MLP decoder，发布实现的最后一层具体为线性层。

**Flow Matching 的训练任务**：取一份目标布局 x1 和随机初始坐标 x0，随机选择 t∈[0,1]，构造中间坐标，再让网络预测从噪声走向目标布局的速度。

```text
x0：从 [-1,1] 均匀采样的初始坐标
xt = (1-t) × x0 + t × x1
目标速度 = x1-x0
loss = 可动节点上的均方误差 MSE(vθ(xt,t,G), x1-x0)
```

这是有明确速度目标的监督训练，不是通过 placement reward 训练 RL。发布配置记录的优化器为 Adam，学习率 3×10⁻⁴、batch size=64、train_steps=1,000,000、训练 seed=61、参数量 6,285,058。train_steps 是配置预算，不能据此认定 best.ckpt 就是最后一步，也不能确定论文选择 checkpoint 的完整规则。

**本次复现没有执行上述训练**：直接加载官方 best.ckpt，对六个真实电路进行零样本生成。生成 seed=300；固定训练权重不代表每次初始坐标相同，生成时的随机流另行控制。

## 第三部分 采样阶段的约束与优化

网络预测速度本身不能保证无重叠。FlowPlace 在每一步执行“预测终点 → 把终点修正为合法布局 → 更新当前坐标”，不是生成结束后才统一处理重叠。

1. 用当前速度外推终点：u1 = xt + (1-t) × vθ(xt,t,G)。

2. 对 u1 做贪心网格合法化。在 128×128 网格上排除越界和与已放置宏重叠的候选；固定端口保持不动，可动宏在合法候选中选择代价最低的位置。

3. 代价由“到预测位置的距离”和“规整度偏好”组成，权重分别为 1.0 和 0.1，两项分别归一化。代码的规整度具体偏向宏中心靠近可行区域四角；每侧增加 0.001 的归一化 padding。

4. 按下一时刻更新坐标，重复 20 个步骤。本次关闭额外 HPWL/overlap 梯度引导，guidance_mode=none、grad_descent_steps=0。

这里有两处复现必须注明的代码细节。**论文公式与发布采样更新存在差别**：论文插值使用最初噪声 x0，发布代码使用当前坐标 xt。本次保留发布代码，没有自行改成论文公式或普通 Euler 更新：

```text
论文：x_next = (1-t_next) × x0 + t_next × 修正终点
代码：x_next = (1-t_next) × xt + t_next × 修正终点
```

此外，发布合法化器虽然计算了面积排序，实际处理顺序仍为固定节点后接原顺序可动节点；找不到合法网格候选时会保留原坐标。因此不能单凭“开启 hard constraint”就宣称任意输入都保证合法。本次对六份生成布局另做宏重叠和越界检查，六份均通过；这仍不代表后端详细布线 DRC=0。

## 复现步骤

1. **固定输入与模型**：核对官方发布权重、源码版本、六个电路的网表/SDC 及工艺文件；严格加载 checkpoint，不进行每电路微调。

2. **生成宏布局**：seed=300 在模型初始化之前设置一次，依次处理 ariane133、ariane136、bp_be、bp_fe、bp、swerv_wrapper。使用同一条全局随机流，不是每个电路重新设置 seed；按官方采样代码执行 20 步约束生成。

3. **保存生成证据**：保留初始噪声、生成坐标、配置和运行记录。GPU 原始运行仍有数值非确定性，固定 seed 不足以保证跨运行、跨硬件逐位相同，具体输入以保存的坐标为准。

4. **检查与转换**：独立检查宏无重叠、无越界，再通过 DEF adapter 转换，并核对宏 ID、尺寸、坐标尺度与方向。bp_fe 与官方转换结果的往返检查达到字节一致；不能据此推广为所有转换细节都已完全对齐。

5. **运行作者后端**：执行发布流程的 `make run_mp` 导入宏位置，再执行 `make run_wo_synth`。复用 `1_synth.v`、`1_synth.sdc`，继续完成标准单元放置、时钟树、全局与详细布线及最终报告。

6. **统一提取与核查**：rWL 读取 `5_2_route.json`，最终 WNS/TNS、功耗和标准单元面积读取 `6_report.json`；同时检查 DRC、最终 DEF 宏几何和日志状态。保留原流程主组，不用后续坐标导入修正组覆盖它。

每个电路使用在后端评估前固定的一份布局，没有按最终 PPA 从多个生成结果中挑选。重跑同一输入的基础设施失败任务不算新的独立 seed。

单电路生成用时约 0.36～3.75 秒，包含对应调用中的合法化初始化及编译开销，不含模型加载和完整后端。下表另列后端耗时。

## 布局合法性与稳定性

六份生成布局均通过宏块无重叠、无越界检查；原流程六个最终 DEF 的宏几何检查也通过。但作者后端的 place_macro 会对齐布线轨道，最终坐标与生成器输入坐标存在差异，不能写成宏位置完全未变。

详细布线完成不等于 DRC=0。本组为 6/6 完成后端评估、0/6 达到零 DRC；宏块合法也不等于标准单元、电源网络和信号布线全部满足签核要求。

目前主对照使用一个官方 checkpoint、一条 seed=300 的生成流，每个电路一份固定布局。没有完成多生成 seed 的完整后端统计，也没有多个训练 seed 的模型。因此，这里不报告均值、标准差或“稳定达到论文水平”。即使补做多个生成 seed，也只能衡量同一模型的生成波动。

## 当前结论

官方模型生成与完整后端评估已经在六个电路上跑通，面积和功耗接近论文；线长和时序仍存在差异，全部结果留有 DRC。因此，当前成果可以作为可追溯的复现记录，尚不宜表述为 Table 2 全面复现成功。

后续作为 Flow-Q 的正式 baseline 时，需要预先固定统一的宏导入方式、工具版本、布线修复预算和布局选择规则，并分别报告 PPA、DRC 及计算成本。当前单 seed 结果不能支持稳定性结论。
