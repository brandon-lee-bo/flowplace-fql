# Scalar control: fixed final-route adapter

This addendum preserves the original four-arm manifest's72 detailed-route
identities, T0/T2 only, first four evaluation indices, three training seeds.
The three FQL branches share the same actual T0; its12 DRT outputs are
measured once. No collection, reward, checkpoint or layout selection is added.
Independent preflight review caught that the original `socdrt1_` run IDs would
be rejected by the unchanged archive helper, which accepts `go2o_` runs. This
addendum prospectively prefixes only those72 execution run IDs with `go2o_`.
The full route plan records the exact translation, a canonical SHA256 of the
original72-task inventory, and the original manifest binding. Keys, inputs,
outputs, sampling indices and every physical setting stay fixed. No route was
launched before this correction, and the frozen base manifest is not rewritten.
All final outcomes remain evaluation-only. The final round is the primary
endpoint; intermediate-round GRT is still reported separately.

`tools/qstudy_scalar_online_control_route.py` references both sealed base and
continuation manifests. It has two explicit phases: source preparation, then
72 independent route tasks, at most two concurrent. Source preparation waits
for complete native continuation receipts. Each original export verifier and
native GRT checker admits the actual producing actor, raw/executed/noise
arrays, legal geometry and DEF/native correspondence before source sealing.
Missing saved geometry audits are errors; the source inspector cannot invoke
EDA to create them. Common noise hashes are checked across all72 sources.

The route task rechecks its exact sealed source, invokes the unchanged
`fql.graph_o2o_full_route` measurement, then uses the original final native
auditor. Eight threads, Nangate45/container/physical revision, scratch archive
storage and cap20 remain fixed. There is no new resident route controller.
Resource requests are two CPUs/8GiB/20minutes for sealing, and eight CPUs/
12GiB/150minutes per route task. PREEMPTED/NODE_FAIL/BOOT_FAIL may recover
only missing tasks for at most three array generations under the inherited
submission journal. Other errors require diagnosis, never invented bad PPA.
The original physical worker reuses a successfully completed preserved route
when only outcome publication was interrupted.

Confirmed upstream physical failures remain in the72-request denominator
without an actual detailed-route invocation or fabricated metrics. Completed
routes with DRC>0 retain all measured metrics and their DRC count. Final WL,
WNS, TNS, power, standard-cell area and DRC are reported separately from the
GRT eight-noise population; GRT overflow is not final routed congestion.
Power remains the common default-activity tool estimate. This adapter creates
no final report and makes no claim of PPA improvement.
