## 还不能称为严格数值复现的原因

1. **许可证尚不可用。** 共享 license 文件已经通过 Slurm 实测失败，需要实验室实际使用的环境脚本或有效许可证服务器配置。
2. **作者没有公开 ICCAD 商业工具评估脚本。** DREAMPlace 参数暂用固定版本自带 ICCAD 配置；Innovus 的 RC、时序视图、时钟处理及统计口径需要进一步核对。`scripts/innovus_egr.tcl` 是未执行的重建草稿。
3. 当前 DREAMPlace 是 **CPU 版本**；不与论文 GPU 耗时比较。只对旧 OpenTimer 的测试程序做了 glibc 兼容补丁，未改放置/时序算法。
4. 发布 DEF 中 superblue1/3/4/16 有正面积宏块重叠，superblue10 有一个宏块越界；没有偷偷修坐标。superblue18 是先验证流程的电路，尚未完成八电路 PPA。

没有用 OpenROAD 或 OpenTimer 的结果替代 Innovus 的 rWL、rO-H/rO-V、WNS、TNS。

## 13:48 补测：正常登录及共享 EDA 环境仍不能启动 Innovus

按用户要求，读取实验室 PDF 后在 `enterprise` 通过 Slurm 重测（1787702、1787703）。
第二个作业实际在完整 Bash 登录 / Zsh 交互登录 shell 中启动程序，并补测了共享初始化脚本。

| 实测方式 | 结果 |
| --- | --- |
| Bash 登录 shell | CDS_LIC_FILE / LM_LICENSE_FILE 为空；LMC-01902 |
| Zsh 交互登录 shell | 同上；LMC-01902 |
| 共享 Cadence license.dat，默认搜索 | IMPLIC-4：No valid licenses found for this product |
| 共享文件，CDS_LIC_ONLY=1 | 同上 |
| source setup_eda.env 后使用共享文件 | 同上；工具日志确认同时搜索共享文件和学校服务器 |

`setup_eda.env` 配置的学校许可证服务器可连接，`lmstat` 返回 license server UP，
但显示的 vendor daemon 是 **snpslmd（Synopsys）**；这不是已验证可用的 Cadence 服务。
共享 Cadence 文件没有 SERVER 行，`lmstat -s` 无法据此查询网络许可证服务；
这本身不证明所有形式的本地许可证都无效，真正的失败证据是上述 Innovus 启动结果。

五种方式均未执行到测试 Tcl；版本查询成功不能算工具可用。结论限于当前账户、
enterprise 节点和已找到的配置，不能据此断言其他人没有可用环境。
下一步所缺是可正常启动 Innovus 的 Cadence 初始化脚本或有效 CDS_LIC_FILE 配置。

原始作业日志：`logs/innovus_retry_1787703.log`。
完整测试输出：`/scratch/bohanli/flowplace_iccad/innovus_retry_1787703/`。
其中 JSON 的 `license_environment` 是启动 shell **之前**的输入环境；
`source setup_eda.env` 后的实际搜索路径以对应 Innovus `probe.log` 为准。
